# Чек-лист приёмки ТЗ (раздел 10) — Кейс №2

Статусы: ✅ выполнено и проверено · ⚠️ выполнено частично · ❌ не выполнено

| № | Критерий ТЗ | Статус | Как проверено |
|---|---|---|---|
| 1 | Создание, редактирование и удаление привычек работают корректно | ✅ | Ручные сценарии в браузере: создание, редактирование (смена названия/расписания), удаление с подтверждением (отмена и подтверждение); тосты |
| 2 | Ежедневная периодичность и выбранные дни недели | ✅ | Юнит-тесты `habits.test.ts` (daily/weekly/пустые дни/до даты начала) + ручная смена расписания на «Пн, Ср, Пт» с проверкой статуса за сегодня |
| 3 | Отметки выполнения сохраняются для конкретных дат | ✅ | Дата отметок на экране «Привычки»; отметка/отмена; `reports.test.ts` (completed=false не считается); восстановление после перезагрузки |
| 4 | Данные сохраняются после повторного открытия приложения | ✅ | Отметка привычки → открытие новой вкладки (полная перезагрузка) → привычка, отметка и серия восстановлены из localStorage |
| 5 | Создание, редактирование, завершение и удаление задач корректны | ✅ | Ручные сценарии: создание (со сроком и без), редактирование срока, выполнение, возврат в работу, удаление с подтверждением; `tasks.test.ts` |
| 6 | Дневной отчёт правильно рассчитывает запланированные и выполненные действия | ✅ | `reports.test.ts` (13 сценариев: пустые состояния, проценты, отменённые отметки) + сверка на экране «Отчёты» с ручным расчётом |
| 7 | Статистика за 7 дней по сохранённым данным | ✅ | `reports.test.ts`: границы окна, дни вне периода, расчёт по запланированным; сверка на экране |
| 8 | Интерфейс адаптирован под смартфон | ⚠️ | Mobile-first CSS (одна колонка, крупные цели ≥48px, safe-area, нижний таббар); Lighthouse Accessibility 1.0. **Эмуляции мобильного окна в среде нет — реальный смартфон не проверялся** |
| 9 | Пустые состояния и ошибки обрабатываются корректно | ✅ | Пустые списки, день без запланирований («н/д» вместо процента), валидация форм, баннер ошибки сохранения, повреждённый JSON в хранилище |
| 10 | При серверной реализации данные пользователей изолированы | ⚠️ | Код готов: проверка Telegram-подписи на сервере, данные в мета-полях WP-пользователя, доступ только «свой». **На живом WordPress не проверялось** (сервера в среде нет) |
| 11 | Приложение проверено непосредственно в Telegram Mini App | ❌ | Нет публичного HTTPS-домена и настроенного бота. Клиентская обёртка WebApp API есть; сценарий в Telegram не прогонялся |
