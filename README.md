# TrackTel — трекер привычек и задач для Telegram Mini App

Учебный MVP по техническому заданию «Кейс №2: Трекер привычек и задач для Telegram Mini App».

Приложение помогает вести привычки, управлять задачами, отмечать выполнение по датам,
просматривать дневные отчёты и статистику за 7 дней.

> **Важно о режиме хранения.** По умолчанию приложение работает в **«Тестовом режиме»**:
> данные сохраняются локально в браузере (localStorage) и не покидают устройство.
> Это локальный прототип, а не многопользовательское приложение.
> Серверный режим (WordPress REST API) подготовлен кодовой основой и включается
> переменной окружения (см. «Подключение WordPress») — он **не проверялся на живом
> сервере** в рамках этой сборки.

## Стек

- **Frontend:** React 19, TypeScript, Vite
- **Тесты:** Vitest (расчёты отчётов, серий, дат, сортировки задач)
- **Telegram:** Telegram Web Apps API (тема, initData, вьюпорт)
- **Серверная часть:** WordPress + REST API (плагин `wordpress-plugin/tracktel`)

Лишние библиотеки не использовались: навигация, формы, модальные окна и хранение
реализованы на стандартных средствах React/браузера.

## Требования к окружению

- Node.js 20+ (проверено на Node 24)
- npm 10+ (проверено на npm 11)
- Для серверного режима: WordPress 6.0+ с PHP 7.4+ и HTTPS
- Для запуска в Telegram: аккаунт Telegram и токен бота (только на сервере)

## Установка и запуск

```bash
cd client
npm install          # установка зависимостей
npm run dev          # дев-сервер (http://localhost:5173)
npm run typecheck    # проверка типов
```

## Переменные окружения

Файл `client/.env.local` (шаблон — `client/.env.example`). Секретных значений здесь нет.

| Переменная | Значения | Назначение |
|---|---|---|
| `VITE_DATA_BACKEND` | `local` (по умолчанию) / `wp` | Какое хранилище использовать |
| `VITE_WP_URL` | URL WordPress, например `https://example.com` | Базовый адрес API (без `/wp-json`) |

**Токен бота в клиентские переменные и в клиентский код класть нельзя** — он нужен
только серверу (см. ниже).

## Подключение WordPress

Кодовая основа лежит в `wordpress-plugin/tracktel/` (пока **не проверялась на живом
WordPress** — в среде нет сервера и PHP; перед эксплуатацией требуется проверка):

1. **Установка плагина:** скопировать папку `wordpress-plugin/tracktel` в
   `wp-content/plugins/tracktel` и активировать «TrackTel» в админке.
2. **Токен бота** — только в `wp-config.php` (на сервере, не в git и не в клиенте):

   ```php
   define( 'TRACKTEL_BOT_TOKEN', 'сюда_токен_от_BotFather' );
   ```

3. **Что делает плагин:**
   - маршрут `GET /wp-json/tracktel/v1/ping` — проверка, что плагин активен;
   - `GET /wp-json/tracktel/v1/data` и `PUT .../data` — чтение/запись данных пользователя;
   - **каждый запрос** проходит серверную проверку заголовка
     `X-Telegram-Init-Data` (HMAC-SHA256 по спецификации Telegram, свежесть `auth_date`
     ≤ 24 ч). Без корректной подписи — `401`;
   - Telegram ID связывается с WP-пользователем **только после проверки**; данные
     хранятся в мета-полях WP-пользователя и изолированы между пользователями;
   - токен бота и проверка подписи выполняются **только на сервере**.
4. **Включение серверного режима на клиенте:**

   ```bash
   # client/.env.local
   VITE_DATA_BACKEND=wp
   VITE_WP_URL=https://ваш-домен.ru
   ```

5. В интерфейсе бейдж хранения меняется с «Тестовый режим» на «WordPress».

## Настройка Telegram Mini App

1. Создать бота у **@BotFather** → `/newbot` → получить токен (остаётся на сервере).
2. У бота: `/newapp` (или `/setmenubutton`) — указать HTTPS-URL приложения
   (для разработки — туннель вроде ngrok/cloudflared; `localhost` Telegram не открывает).
3. Открыть приложение в Telegram → WebApp Apps API предоставит `window.Telegram.WebApp`
   (`initData`, тема, вьюпорт). Вне Telegram приложение работает как обычное веб-приложение,
   но серверный режим недоступен (нет `initData`).
4. Клиент передаёт `initData` **заголовком** на сервер; сервер проверяет подпись.
   Никаких секретов клиент не содержит.

## Известные ограничения

1. **Данные локальные** (тестовый режим): не синхронизируются между устройствами — это не
   многопользовательское приложение, пока серверный режим не подключён и не проверен.
2. **Плагин WordPress не проверен на живом сервере:** в среде нет WordPress и PHP
   (даже `php -l` недоступен). Код следует официальным API WP, но требует проверки.
3. **Критерий «проверено непосредственно в Telegram» не выполнен:** нет публичного
   HTTPS-домена и настроенного бота. Клиентская обёртка WebApp API готова и деградирует
   без Telegram, но сценарий в Telegram не прогонялся.
4. **Серия (streak) приостановленной привычки равна 0**, период паузы не сохраняется
   как история: в дневном отчёте приостановленная привычка не считается запланированной.
5. Смена `startDate`/расписания влияет на расчёт будущих и прошлых отчётов по текущему
   расписанию (историческая реконструкция расписания не ведётся).
6. Тестовые данные отделены только фактом локального хранения: отдельного «демо-режима»
   с сидами нет; в серверном режиме пользователь работает со своими записями.
7. GitHub-репозиторий и публичная ссылка не создавались (нет доступа к удалённому репозиторию).
